## 已实现的软件行为

Acl 支持二选一的 number 或 name。编号沿用 Comware 2000–3999；命名 ACL 必须显式 acl_type=basic/advanced，名称按厂商规则不区分大小写，保留字 all 拒绝。本实现的名称限定为字母开头、1–63 个 ASCII 字母/数字/下划线/点/连字符。编号与类型冲突、重复规则/方向绑定及输入控制字符拒绝。

source/destination 接受原 CIDR、any、host IPv4、IPv4 wildcard。wildcard 不要求连续，忽略位归零后按真实匹配位比较；不同匹配位不能由格式别名掩盖。上游 ahp/eigrp 及 esp 转为协议号 51/88/50；本机帮助列出的 20 个 ICMP 名称可转为 type/code。旧数字端口与新运算字段保持兼容。原生回读支持 wildcard=0 的主机简写。

回读按已知名称和类型选择唯一 ACL；命名配置与显式编号+名称的别名可关联，其他编号不能冒用。名称/类型冲突、重复头和 match-order auto 在修改前拒绝，避免把自动排序当作请求顺序。同 ID 旧规则清除后再写，其他规则、ACL 名称和配置保留。

请求方向上的旧 IPv4 packet-filter 先逐项撤销，再应用本次 ACL，避免 HCL 的多 ACL 绑定累积。反方向及 ipv6/mac/user-defined 绑定保留。失败后的合成恢复覆盖旧过滤器撤销之后的错误；恢复原完整基线，不重放策略。多 ACL 计划的规则清除不会重复发出 undo。

共享部署、备份、恢复及 ping 的合成通道现在只提升 protocol_* 状态。注入通道即使伪造 native_channel 与 VM UUID，也不能提升真实 configuration_verified、backup_verified、rollback_verified 或 connectivity_verified。备份内的 restore_test_verified 同样区分原生证据与 protocol_restore_test_verified。
