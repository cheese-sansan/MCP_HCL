# ADR-0001：分支整合和共用事务助手

状态：Accepted。日期：2026-10-11，Asia/Tokyo。

## 背景

`main` 停留在初始提交，`dsh-2` 与 `codex/hcl-live-parity` 分叉；最新 0.5.0 功能和验证仍存在于不同工作区的未提交文件。代码混用密集单行语句和导入顺序，多个功能从 NAT 实现模块导入通用助手，维护关系不清晰。

## 决策

在干净整合工作区合并两条分支历史，再纳入逐文件备份的最新已验证源码。保留所有来源分支、工作区和 Git bundle。旧分支独有宿主脚本与冲突历史文档归档；最新严格合同和退役保护为当前实现。没有重启或重新开放旧宿主变更入口。

采用自动 Ruff 格式化和排序导入，以 AST 和完整 SDK 声明对比验证行为保持。错误码、工具参数、默认门控、返回字段与原生证据限制不改变。

将交换预算和 JSON/历史记录助手从 `nat_policy.py` 移到 `transactions.py`，函数/类主体保持原 AST。接口调优、交换安全、NetStream 直接依赖该模块；NAT 保留原助手名称的兼容导出。业务备份、恢复与命令顺序继续属于各功能服务，不合并成新的通用事务状态机。

## 后果

源码与历史进入一个本地 main，开发者可使用统一检查入口。旧 wheel 的 SHA 与历史验证继续有效于旧范围；重构后的源码必须绑定新的 manifest 和 wheel SHA。格式化的较大差异与功能变更分开提交。

软件检查不证明尚缺的原生 CLI、配置/startup、流量或完整上游行为等价。发布或删除来源分支不由本次本地整合自动授权。
